# 1. Global API conventions

### Base URL

```text
/api/v1
```

### Authentication

Since Firebase Authentication is already configured on the frontend:

```http
Authorization: Bearer <FIREBASE_ID_TOKEN>
Content-Type: application/json
```

The backend verifies the Firebase token and derives:

```text
firebase_uid
email
role
```

Application roles remain:

```text
CITIZEN
RESPONDER
COORDINATOR
ADMIN
MEDICAL
SHELTER_MANAGER
```

The backend should **never trust `role` supplied by the client**.

# 3. Emergency Creation

This is the most important request in the entire system.

The emergency lifecycle is:

```text
CREATED
→ SYNCED
→ VALIDATED
→ PRIORITIZED
→ POLICY_SURFACED
→ ASSIGNMENT_PENDING
→ ASSIGNED
→ IN_PROGRESS
→ RESOLVED
```

This is defined in the updated workflow. 

## 3.1 Create Emergency — Online

```http
POST /api/v1/emergencies
```

### Complete request payload

# 6. Disaster Zone Resolution

The architecture resolves GPS coordinates to a PostGIS disaster zone. 

```http
POST /api/v1/zones/resolve
```

### Request

```json
{
  "latitude": 16.5062,
  "longitude": 80.6480,
  "disaster_type": "FLOOD"
}
```

### Response

```json
{
  "matched": true,

  "zone": {
    "id": "Z04",
    "name": "Ward 7 - Flood Zone Alpha",
    "zone_type": "FLOOD",
    "jurisdiction": "Krishna District, Andhra Pradesh"
  },

  "active_disaster_types": [
    "FLOOD"
  ]
}
```

If no zone:

```json
{
  "matched": false,
  "zone": null,
  "reason": "NO_ACTIVE_ZONE_MATCH"
}
```

# 14. Dynamic Replanning Request

The replanning workflow is:

```text
OBSERVE
→ UNDERSTAND
→ PLAN
→ VALIDATE
→ APPROVE
→ EXECUTE
→ MONITOR
```

as specified in the execution workflow. 

```http
POST /api/v1/decision/replan
```

### Request

```json
{
  "trigger": {
    "type": "ROAD_BLOCKED",
    "entity_id": "R12",
    "event_id": "EVT-ROAD-001"
  },

  "current_state": {
    "assignments": [
      {
        "assignment_id": "A-1001",
        "emergency_id": "E101",
        "resource_id": "R03",
        "route_id": "ROUTE-101"
      }
    ],

    "resources": [
      {
        "id": "R03",
        "availability_status": "AVAILABLE"
      },
      {
        "id": "R05",
        "availability_status": "AVAILABLE"
```
